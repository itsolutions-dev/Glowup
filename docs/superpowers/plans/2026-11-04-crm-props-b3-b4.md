# CRM props B3/B4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Five optional additions to `@its/glowup-ui` the CRM's screens draw today: typed `ToggleButtonGroup`
values with tooltips, `Skeleton preset="list"`, a new `DayTimeline`, `Stepper` dots/progress with Back/Next,
`Dialog` `overline`/`leadingActions`/`dividers`.

**Architecture:** Each is an optional prop (or one new component) whose default keeps today's output. Tests first in
`packages/ui/src/__tests__` (run as iOS and Android); each task brings its changeset and playground wiring; one
final task regenerates the committed generators and updates the docs.

**Tech Stack:** React Native 0.86 / react-native-web, jest-expo, `@testing-library/react-native`, changesets.

**Spec:** `docs/superpowers/specs/2026-11-04-crm-props-b3-b4-design.md`

## Global Constraints

- Every new prop optional; with it left out, the component renders as today (existing tests stay green unchanged).
- Colours, radii and spacing from the theme (`theme.colors`, `theme.shape`, `theme.spacing`); icons through `Glyph`.
- No new dependency. No `.localeCompare(` / `toLocaleString(` with a locale in hot paths (Hermes cost, 3/11).
- One changeset per task, `"@its/glowup-ui": minor`, wording like `.changeset/week-strip.md`.
- Relative imports inside `packages/ui`; new public names exported from `src/index.ts`.
- **One commit at the end** (Alice's rule: commit at the end of a large implementation, never push).

## Review Focus

1. `ToggleButtonGroup` with `false`, `null` and `true`: each selects only its own segment (`false` ≠ `null`), and two
   options never share a React key → Task 1 test "keeps null, false and true apart".
2. `ToggleButtonGroup multiSelect` with numbers: toggling adds/removes by `===` → Task 1 test "toggles typed values".
3. `DayTimeline` events given out of order are shown by start time → Task 3 test "orders the events by start".
4. `Stepper` on the last step without `submitStep`: Next disabled; on the first step without `onCancel`: Back
   disabled → Task 4 test "disables Back and Next at the ends".
5. `Dialog` with `leadingActions` but no `actions`: the row is still drawn and the fallback close button is not
   replaced unexpectedly → Task 5 test "draws leading actions without trailing ones".

- Produces:
  ```ts
  export interface DayTimelineEvent {
    id: string | number;
    title: string;
    start: Date;
    end: Date;
    /** Small line above the title (the CRM: "Appuntamento" / "Richiamo"). */
    overline?: string;
    /** After the times: "09:00 – 09:30 · note". */
    note?: string;
    /** #RRGGBB; tints the card (toneFromColor) and draws a 4 px bar on its start edge. Defaults to theme primary. */
    color?: string;
    /** Grey, struck through. */
    canceled?: boolean;
  }
  export interface DayTimelineProps {
    events: DayTimelineEvent[];
    onEventPress?: (event: DayTimelineEvent) => void;
    loading?: boolean; // Skeleton preset="list" count 4 itemHeight 72
    emptyState?: EmptyStateProps; // default { icon: "calendar-blank-outline", title: "Nothing scheduled" }
    style?: StyleProp<ViewStyle>;
    testID?: string;
  }
  ```

### Task 4: `Stepper variant="dots" | "progress"` with Back / Next

**Files:**

- Modify: `packages/ui/src/components/Stepper.tsx`
- Test: `packages/ui/src/__tests__/stepper-dots.test.tsx`
- Create: `.changeset/stepper-dots-progress.md`

**Interfaces:**

- Consumes: `Button` (`variant: "text" | "filled"`, `type?: "button" | "submit"`, `icon`, `iconPosition`, `onClick`, `disabled`, children = label), `LinearProgress` (`progress` 0..1).
- Produces: `StepperProps` gains
  `variant?: "steps" | "dots" | "progress"` (default `"steps"`, today's), `steps: Step[] | string[] | number`,
  `onBack?: () => void`, `onNext?: () => void`, `backLabel?: string` (default "Back"), `nextLabel?: string` (default "Next"),
  `submitStep?: boolean`, `onCancel?: () => void`.
- Dots/progress row: `[Back] [indicator] [Next]`, buttons `flex: 1` so the indicator is centred (as the CRM's sx). Buttons
  are drawn only when `onBack`/`onNext` (or `submitStep`/`onCancel`) are passed. Back: `variant="text"`, `chevron-left`;
  on step 0 it calls `onCancel`, disabled without it. Next: `chevron-right` end icon; on the last step disabled unless
  `submitStep`, which makes it `variant="filled" type="submit"`, labelled `nextLabel`.
- Indicator: dots = `count` circles 8 px, active `primary`, others `outlineVariant`; progress = `LinearProgress`
  with `progress = activeStep / (count - 1)` (0 for one step). The indicator is one accessibility element:
  `accessibilityRole="progressbar"`, label `"Step {activeStep+1} of {count}"`, `accessibilityValue {min:1,max:count,now:activeStep+1}`.
- A number in `variant="steps"` draws that many numbered circles without labels.

- [ ] **Step 1: Failing tests:**
  - "draws one dot per step, the active one in primary": `variant="dots" steps={4} activeStep={1}` → label "Step 2 of 4", 4 dots, dot 1 background `theme.colors.primary`.
  - "moves with Back and Next": press "Next" → `onNext` once, press "Back" → `onBack` once.
  - "disables Back and Next at the ends": step 0 without `onCancel` → Back `accessibilityState.disabled`; last step without `submitStep` → Next disabled; step 0 with `onCancel` → pressing Back calls `onCancel`, not `onBack`.
  - "submits on the last step": `submitStep` on the last step inside a `Form` with `onSubmit` → pressing the Next button calls `onSubmit`.
  - "shows the progress bar": `variant="progress" steps={5} activeStep={2}` → a `progressbar` whose `LinearProgress` gets `progress` 0.5.
  - "leaves the labelled stepper unchanged": no `variant` → same output as today (existing `stepper` tests green).
- [ ] **Step 2: Run** `npm test -w @its/glowup-ui -- stepper-dots` → FAIL.
- [ ] **Step 3: Implement** in `Stepper.tsx` (a `count` from `steps`; the dots/progress branch returns early before `renderStep`).
- [ ] **Step 4: Run** `npm test -w @its/glowup-ui -- stepper` → PASS.
- [ ] **Step 5: Changeset**, preview examples "Dots" and "Progress, submit on the last step" in `.design-sync/previews/Stepper.tsx`, registry control `variant` for Stepper.
